# 1.5.0: what the neighbours do better, taken

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. No `tests/test_*.py` files (a global hook forbids the model writing tests): every behaviour is proven by a live command in the report and a step in `.github/workflows/ci.yml`; `tests/golden/expected/` stays byte-identical unless the commit message names the moved lines; `tests/golden/maps/*/framework_map.json` regenerate when a key is added.

**Goal:** A survey of the popular projects in this space (`.superpowers/sdd/2026-09-05-everything/landscape-2026-09.md`, read the section for each task before starting it: it names the source project, the exact mechanism, the constraints and the CI proof) found nine things worth taking. This plan takes them. Structural pattern search (item 8 there) is deliberately not taken: it is the first tool whose availability would vary by language, and ast-grep already does it well.

**Architecture:** every task is additive over `framework_map.json` (`where-are-we/1` gains keys, never changes one) or a new output file or a new tool composed from `ask.py`'s existing functions. Extraction changes sit in `_mapper/declare.py` (spans) and `_mapper/build.py` (xrefs, rank, content hashes); tools in `ask.py`, `mcp.py`, `cli.py`; renderers in `_mapper/render.py`. Each task ends with SCHEMA.md rows for its keys, README rows for its flags and tools, a CHANGELOG line under `## 1.5.0`, and its CI step.

**Global constraints:** stdlib only in the core (`hashlib`, `ast`, `json`, no networkx: write the forty-line power iteration); deterministic output (sorted iteration, ties by path then line, floats rounded before sorting); Python 3.12+; no em dashes or en dashes in new prose; CI negations as `if cmd; then exit 1; fi`; every new MCP tool also a CLI flag with byte-identical output; every new key in SCHEMA.md (the coverage step must stay at N keys / N rows); no LLM anywhere; comments say what is there; commit trailers `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01Qt2xWwtUxwkeWyJt5hHgi7`.

### Task 1: `spans`, multi-home `defines`, and `at FILE:LINE` (landscape item 1)

New key `spans`: `{name: [{"file", "start", "end", "kind"}]}` listing every declaration site, sorted by file then start. Python from `ast` (`end_lineno`), tree-sitter `end_point` under `[precise]`, regex languages report `"end": null` and `defines` prints `file:10-?`. `definitions` keeps its shape (first site) for compatibility. `--defines NAME` / MCP `defines` list every home: `charge: a.py:10-24 (function), b.py:88-91 (function)`. New `--at FILE:LINE` / MCP `at`: the whole enclosing definition text for a line (bounded by the answer budget, whole lines, a tail with a `more:` handle if cut), or `no definition encloses FILE:LINE (nearest: ...)`.

Proof (CI step "a name declared twice names both files, with its span"): fixture with `charge` in `a.py:10-24` and `b.py:88-91`: `--defines charge` prints both in path order; `--at a.py:15` returns lines 10 to 24 and `ast.parse` accepts the text; a regex-language name prints `file:N-?`; two builds byte-identical; golden maps regenerated with the new key, expected unchanged.

### Task 2: `context NAME` (item 2)

One budgeted answer composing `definitions_for` (now spans), the signature row from `ask`, `callers`, `callees`, `impact` at depth 1 (stated in the first line). Fixed budget shares per block; each block ends with its tail and `more:` handle; whole rows only. MCP `context`, CLI `--context NAME`. No new key.

### Task 3: `rank` and `--files` (items 3 and 9)

Graph: nodes are files; an edge from a referencing file to a defining file per identifier, weight `sqrt(refs)`; multipliers copied from aider: x10 for an identifier in the query words, x10 for a long snake/kebab/camel name (8+ chars with a separator or case change), x0.1 for a leading underscore, x0.1 for a name more than five files declare. PageRank by power iteration: 100 iterations, damping 0.85, sorted node order, values rounded to 9 digits before sorting, ties by path. Stored key `rank`: the unpersonalised global ranking, top 200 `[{"name","file","line","score"}]`. `--rank FILE[,FILE...]` / MCP `rank(files=[...], words=[...])`: personalised on those files, top N definitions. `--files a.py,b.py` on `--ask` (and `files` on MCP `ask`), plus a newline list on stdin when `--files -`: rows whose path matches are ordered first inside each section, the rest follow with the usual tail.

Proof (CI step "rank puts the file everything calls above the file nothing calls"): fixture where `core.py:charge` is called from ten files and `orphan.py:unused` from none: `--rank billing.py` lists `charge` above `unused`; `--rank` with no files equals the stored `rank` order; a name declared in six files ranks below the same name declared once; byte-identical across two runs and across the CI matrix (compare the two jobs' output via an artifact or a stored expected file); `--ask charge --files billing/` puts `billing/` rows first.

### Task 4: content hashes in the cache and a `content_root` (item 4)

Parse cache key becomes `(path, kind, sha256)` with `(mtime, size)` as the pre-filter: hash only files whose mtime or size changed or whose hash is missing. New key `content_root`: the sha256 over sorted `(path, hash)` pairs of indexed files. `fingerprint` keeps its format. `--diff` (if present; else the `changed_since` renderer) names the files whose hash moved.

Proof (CI step "a same-size rewrite with a restored mtime is still seen"): rewrite `def charge():` to `def refund():` (same length), `touch` the old mtime back, rebuild without `--force`: `--defines refund` found, `charge` absent; on an unchanged tree `WAWE_DEBUG_PARSES=1` reports 0 parses and the warm build time in the README does not regress (state the number).

### Task 5: `--ctags` (item 5)

Writes `<out>/tags` in universal-ctags format: `!_TAG_FILE_FORMAT 2`, `!_TAG_FILE_SORTED 1`, then `name<TAB>file<TAB><line>;"<TAB>kind:<k><TAB>line:<n>[<TAB>end:<n>]`, sorted by name in C locale then by file. Atomic write like every artefact.

Proof (CI step "--ctags writes a sorted, correct tags file"): header present; `LC_ALL=C sort -c tags` passes; a known symbol's row names the file and line the map holds and `sed -n` on that line contains the name; two builds byte-identical; `readtags` check if installed on the runner (`apt-get install universal-ctags` in the step is acceptable).

### Task 6: `--cost` and `--export` (item 6)

`--cost [THRESHOLD]` (`--json` too): every section with rows, bytes, tokens (`bytes/4` labelled `estimate`; exact and labelled with the tokenizer name only when the `[semantic]` extra has one), sorted heaviest first, rows under THRESHOLD bytes hidden. `--export FILE`: one self-contained file: the incompleteness notice, `indexed:` counts, the section list with each section's byte count, then the brief. The internal renderer named `digest` in `_mapper/render.py` is not renamed; the flag is `--export`.

Proof (CI step "the map says what each of its sections costs"): summed section bytes equal `framework_map.md` size minus header within a stated slack; table sorted descending; `--cost 500` fewer rows than `--cost 0`; token column labelled `estimate` without a tokenizer; `--export` file parses back into the same section list; two runs identical.

### Task 7: `xrefs` with a `resolution` on every edge (items 7 and 10)

New key `xrefs`: rows `{"subject": "file:func", "edge": "calls|imports|declares|overrides", "object": "name", "file": "<resolved file or null>", "candidates": [...], "line": n, "resolution": "sole_declarer|import_line|receiver_import|re_export|base_class|ambiguous|local"}` (the closed set matches the rules build.py already applies; every rule names its own value where it writes the edge). `call_graph_files` is rendered from `xrefs` and stays byte-identical to today's rendering. `impact` prints the resolution of each hop in a trailing column. `call_graph_stats.marked` equals the count of `ambiguous` rows per language.

Proof (CI step "every edge says how it was resolved"): on the poly fixture and the 1.4.x receiver fixtures every `call_graph_files` string is reconstructible from `xrefs`; a `?` edge has exactly the `ambiguous` rows its candidate list names; the import-line edge reports `import_line`, the single-declarer `sole_declarer`, the facade `re_export`; `marked == count(ambiguous)` per language; golden maps regenerated, expected unchanged.
